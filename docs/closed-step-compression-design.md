# 闭合 step 与 token 尾部保留方案（设计草案）

推荐以闭合 step 提供安全切点，以 token 预算决定近期原文保留量，再由模型选择连贯
阶段生成摘要。此方案针对[历史审计](history-trace-audit/2026-10-14.md)中的长 turn、
混合 reasoning 作者和来源保护问题；尚未替换当前生产逻辑。

## 安全边界

turn 保留为用户交互与任务归属信息。当前 turn 内的旧内容也可成为候选，但必须属于
已闭合的工作区间：有 step/end，切点通过工具配对检查，没有跨越正在运行的工具或
当前请求。step/end 本身不足以证明所有依赖已结束；活动委派的启动信息与状态仍保护。
压缩结果的原生执行收据在后续成功模型响应消费前也继续保护。

system/developer、instructions/snapshot、当前人类任务输入与 steering、显式保护
内容构成独立保护集合。实际保护按来源 kind/form 和生命周期判断，不由正文中的
“任务已完成”之类文本解除。保护节点形成范围分隔，或通过现有允许的原文附录保留；
不得把 system/developer 降成 user-role 摘要。

## 近期保留

实验起点为：至少保留最近 2 个闭合 step，近期原文目标约 8k–16k heuristic tokens，
另保留当前活动步骤和上述固定保护集合。这些是待校准策略值，不是当前可用配置项。

从最近的闭合工作单元向前回溯，直到同时达到 step 数下限和原文目标预算。边界只能
落在合法切点，不能为了凑 token 截断工具配对。完整单元可能使保留量超过目标预算；
固定保护或开放工具过大时应报告无法满足目标，不偷偷删除它们。

checkpoint 按它在当前 surface 的位置和覆盖的历史理解，不因为新写入日志就将
全部旧内容视为新工作；它是一个不可拆的历史摘要单元。仍需保护新压缩的执行收据。

例如，一个 turn 已结束 120 个步骤，每步约 1k tokens，近期目标为 8k：

```text
固定保护的任务输入/指令
已完成步骤 1–112：可选压缩范围（遇保护节点则分段）
步骤 113–120：保留原文
当前步骤 121、开放工具与活动委派：保护
```

模型可以把前面的连贯阶段替换成 bN，无须等待整个 turn 完成。

## 候选与阶段

插件先从当前 surface 构造合法区间，再按压缩潜力和阶段完整性提供少量候选。
TODO 状态、委派 settlement、修改/验证阶段等可辅助选择切点；这些信号不替代
step 闭合与工具配对校验。模型负责选择主题连贯的范围和摘要正文。

复用日志化 refs 与 alias 的机制，按需公布安全切点和候选，首版最多给 3 个。
需要完善 alias 的编号重放与生命周期，不必每步追加完整索引或动态 system prompt。
候选与 nudge 一起先写标准消息日志；执行时重新确认源节点序列和保护条件。
候选已被其它压缩改变时返回过期/范围变化，不自动扩大范围或把旧摘要套到新内容。

## 触发与收益

触发顺序为：检查压力与近期增长 → 确认存在合法、可能有净节省的范围 → 输出候选
及 nudge → 模型生成摘要 → 重校验 → 标准 compaction 事务提交。

没有候选时不要求模型执行不可能的压缩。预算需要给摘要生成、工具结果与续答留空间，
阈值应与宿主原生 compaction 的时序协调。范围成本仍计算完整 checkpoint，包含
保护/旧块附录；验收额外测完整压缩循环及后续请求成本，不仅报告局部替换节省。

具体优化指标见[上下文压缩评估方案](EVALUATION.md)：先通过安全与续作质量门槛，
再最小化成功任务的完整费用。阶段完成和前缀保留作为候选/收益判断，须计入首轮
缓存失效、摘要成本和剩余工作时域；这些参数需实验校准。

## 混合作者与模式支持

首版可保留现有先消费原生结果的纯调用 cleanup。含正文/reasoning 的压缩调用，在
离开近期保护区后，随完整的历史工作单元进入普通摘要压缩；摘要保留提交状态、
修复及必要决策，已有 checkpoint 承载的事实不重复抄写。原始日志仍可恢复。
这使长期清理依靠已有标准 compaction，而非直接删除 reasoning 或改写历史 assistant。
短期摘要副本成本必须计量；更早清理混合消息另作实验。

来源保护的 kind/form 匹配应先修正。子会话明确使用同一闭合规则或另行声明支持范围。
PTC-only 需要有可用的控制入口；首版不能仅移除 parent guard 并让混合程序中途修改
历史。均只使用公开扩展点，不修改 dsh 核心。

## 首版验收

- 单 turn 120/463 steps 的合成历史中，可在保留目标与近期工作时压缩旧前缀。
- steering、并行工具、异步委派、原生 compaction 与失效 refs 不破坏配对和保护。
- 官方 DeepSeek thinking enabled，及带解释文本的自然输出，验证提交状态与独立召回。
- 比较原 turn 策略和新策略的候选覆盖、拒绝原因、完整周期成本与事实召回。
- 始终保持请求逐字等于 deriveMessages、标准日志可重放、失败不误报提交。

私有历史只用于本地结构统计；模型验证使用合成事实和历史长度/形态，避免发送原文。
长期嵌套块预算与重摘要策略单独评估，不因本方案改善粒度就宣称解决所有增长问题。
