按每个 session 的请求顺序取后三分之一，v3 平均 347.0k、p95 650.2k；
主会话平均 395.7k、子会话平均 339.2k。这只是事后位置诊断，尚未识别阶段，
不能据此直接把“后三分之一”设为压缩条件。

上表为请求加权，长会话产生更多请求。若先求每个有用量 session 的均值再等权
平均，v3 为 152.1k。301 个有用量 v3 session 中，183 个峰值达到 200k（60.8%），
131 个达到 300k（43.5%），28 个达到 500k（9.3%）。主会话含许多短会话，
只有 9/45 个峰值达到 200k；其少数长会话产生大量请求。因此不能声称每个主会话
通常都有 345k，但几百 k 的日常推理负载确实存在且占请求的大部分。

## 旧格式与范围限制

旧 v0 有 43,242 个可计算的记录桶和样本，平均 208.2k、p95 504.4k；部分缓存
字段缺失，故它们是可观测输入下界，不能标为全量精确输入。v0 的 8,808 个精确
total 子集平均 151.1k，存在字段可用性的选择偏差，不能替代整个旧负载。
混合全库的 96,891 个桶和样本平均 236.2k，仅供辅助参考；主结论采用 v3 完整
精确样本。v0/v3 是日志格式版本，不等同于当前插件或 dsh 发行版本。

本轮没有按历史模型/provider/thinking 模式分层，不能据上下文 token 推算历史
官方 DeepSeek API 账单，也不能把历史与 pilot 的比值当作同任务的性能倍数。
统计覆盖所有可用记录，并未根据任务质量挑选有利会话。

v3 包含 72 条全零用量（0.1342%），来自 14 个全零 session；未找到显式测试标记，
来源分类保持 unknown，未事后剔除。仅作敏感性检查，排除后均值为 259,226.366，
比含零值高 0.1344%，不改变长上下文结论。

## 对评估方案的调整

首轮 baseline/DCP 平均 16,227/18,613 tokens；历史 v3 请求均值约为其
16.0/13.9 倍。已有费用上升与缺 usage 的结论仍对首轮配置成立，但不说明长上下文
压缩是否有效：该轮既没有代表性的输入长度，也没有实际压缩动作。

下一轮保留短任务回归层，增加约 100k/200k/400k/600k 的公开或独立合成长阶段
任务；先核实模型窗口与输出余量。任务应真实依赖阶段事实、工具结果与后续约束，
不能靠无关文本填充。分报主/子、长 turn、thinking 和续作质量；通过同一执行状态
的公共休眠前缀 fork 测缓存失效与回本时域，同时保留整任务 A/B、全费用和独立
成功验收。预注册权重与不可测层后再运行，历史原文继续留在本地。

具体要求已同步到 [评估方案 §15](../../EVALUATION.md#15-历史使用负载校准2026-10-14)
与 [规划 §27](../../PLAN.md#27-压缩算法的评估与优化目标首轮开发-pilot-已完成)。
本轮只完成历史审计与方案校准，尚未运行新一轮长上下文真实模型实验。
