# 单场景配对实验：事件账本服务修复

本实验只回答：从同一长对话和文件状态继续完成这个修复任务时，指定一次 DCP
压缩是否节省费用，并能否保留完成任务所需的信息。它是可复现的场景诊断，
不作为普遍质量非劣或所有任务最优的证明。

## 固定场景

一个 Python 事件账本服务需要修复金额精度、重复投递、跨币种、冲正和异常事件
处理。Agent 必须修复 `ledger.py`，重放 `events.jsonl`，输出整数分余额、准确的
处理计数和简短修复说明。公开 smoke test 只覆盖部分情况；独立验收还覆盖乱序、
重复、非法金额和重复冲正，不能仅凭 Agent 的“完成”回复判成功。

公共历史是明确标注的构造调查回放：三个已闭合 turn，真实 fixture 事件的分页
工具结果、初始实现和调查结论。初始 smoke 失败由 runner 独立验证，回放不伪造
此前模型看过的失败收据。历史不伪造模型 usage，不称为私有历史或
自然模型轨迹。4096 个事件的日志用于重现历史使用的长上下文量级；它们属于
任务账本，没有额外无关 padding。实际长度以官方 API prompt usage 报告。

模型先真实消费这份公共历史，在不修改环境、不压缩的共同准备 turn 回复准备
就绪。其费用单独记为 C_P，随后复制完整闭合日志和环境，再开始配对续作。
两边运行同一固定 Docker image，容器内路径均为 `/work`，文件初始 hash 相同，
工作目录、临时目录和可写状态完全独立。容器内不传 API key、不开放网络。

## 干预与限制

两边从开始就具有相同 system 和工具定义，均加载 DCP。实验固定使用手动模式，
关闭自动策略与自动 nudge；保留默认最近两 turn 保护，保护原始用户任务。

- inactive：明确禁止 compress，使用宿主公开 tool guard 拒绝误调用，保持完整历史。
- active：明确允许并要求先压缩已闭合调查范围 `m0001 → m0003`（turn1–2），
  然后真实完成同一个修复任务。turn3 的准备说明、共同准备与当前续作原文保留。

共同准备的 system surface 节点位于 m0004 之前，m0001→m0004 会触及该
受保护节点，运行前回归确认拒绝；不移动指令或放松保护来扩大压缩范围。

权限消息追加到日志末尾；不改变静态 system/tools，不临时改写 LLM 请求。
每次请求保留 `messages === deriveMessages()` 宿主 invariant。
这是实验 harness 中的工具权限控制，不宣称已实现通用生产休眠模式或新的
闭合 step 自动策略。自然触发算法的收益需另测。

公共准备请求只预热共同过去，不用任何一条分支的未来输出预热另一条。
分支顺序在运行前冻结；共享过去不等于缓存完全相同，以官方命中用量核对。
分别展示首次请求、压缩动作、压缩后首请求及后续请求的缓存/费用变化。

## 计量和验收

默认只运行这个场景的一组配对，官方 `deepseek-flash`、thinking disabled，真实
dsh 0.2.0-rc.2；4096-token 输出上限，宿主原生 compaction 两边均保留。
共同准备最多 3 次请求/120 秒/$0.50；每条续作最多 40 次请求/600 秒/$1.00，
预算按未缓存输入保守预留，所有失败、重试、摘要和恢复都计费。

若准备阶段修改文件、压缩、未正常闭合或未就绪，保留 partial 账本并停止分叉。
若实际上下文未达到 100k，记录压力不足，不伪称代表几十万上下文。
若 active 未成功压缩，记录未实现干预；若 usage 缺失，精确节省率保持 unknown。
任何失败不删除、不补猜、不重新运行挑选好结果。

独立验收分别运行完整账本比对和固定边界探针，参考实现与隐藏探针只在 Agent
结束后注入验收进程，不放到模型可读的工作目录。
验收 Python 与候选子进程均以 `-I` 隔离启动，工作目录模块不得覆盖标准库。
两条分支均通过且费用完整，才报告条件续作节省率 `1 - C_A/C_I`；另报模型请求数、输入均值/p95、缓存
读取、输出量、压缩次数、首次失效和累计费用曲线。

实际实验支出为 `C_P + C_I + C_A`；共同准备只在费用账本中出现一次。
可另展示 `C_P+C_I`、`C_P+C_A` 的条件归因费用，不能混成真实累计支出。
构造调查回放之前的自然模型工作费用未测，不宣称整个任务部署收益。

pnpm eval:scenario             # 只生成公开夹具与协议，不调用 API
