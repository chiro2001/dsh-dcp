# 上下文压缩评估方案

> 状态：2026-10-14 的评估设计，作为后续算法实验的依据；评估 runner 与新算法尚未实现。
> 当前实现与真实回归见 [PLAN §24–§25](PLAN.md)，历史结构见
> [trace 审计](history-trace-audit/2026-10-14.md)，候选算法见
> [闭合 step 与 token 尾部草案](closed-step-compression-design.md)。

推荐目标：**在任务质量和安全性达标的前提下，最小化每个成功任务的端到端费用**。
阶段完成、摘要长度、剪除位置与前缀缓存都是达到这个目标的手段。压缩后能继续正确
工作才算有效；必须将生成摘要、失败、重读及后续全部请求一起结算。

## 1. 主指标与比较规则

一个评估任务包含初始目标、阶段间继续工作、预设后续需求，以及根会话与全部子会话。
实验前固定任务集合、成功条件、停止条件和执行预算；不能由候选算法决定只做哪些
任务。新需求与阶段重开按预先定义的分布进入评估。

对于算法 `π`，一次任务运行 `i` 的总费用为 `C_i(π)`，独立验收成功为
`Y_i(π) ∈ {0,1}`。全部任务和预定重复都进入计量；统计时仍以独立任务为簇。
在同一组任务上的主指标为：

```text
K(π) = Σ_i C_i(π) / Σ_i Y_i(π)                 每个成功任务的费用，越低越好
S(π) = 1 - K(π) / K(baseline)                 相对基线的有效节省率
Q(π) = Σ_i Y_i(π) / N                        任务成功率
```

分子包含失败任务在失败前花掉的费用。没有成功任务时 `K=∞`；基线没有成功任务时
不计算相对节省率。这个指标描述固定工作负载上的成功产出成本，不承诺重复同一失败
任务能按相同概率成功。

按以下顺序选择方案，不将所有因素混成一个加权分数：

1. **硬安全门槛**：日志/请求不变式、工具配对、保护内容、状态恢复等检查全部通过。
2. **质量非劣门槛**：整体和预先指定的关键分层达到质量门槛，关键约束检查全通过。
3. **成本优化**：在通过门槛的方案中比较 `K`、`S` 及任务配对的费用差置信区间。
4. **运行体验门槛**：完成时间、超时率和尾部延迟符合预注册预算；同等成本时优先
   更快、恢复更少、实现更简单的方案。

`K` 单独仍可能奖励牺牲少数高成本任务，必须结合质量门槛和固定停止规则使用。
不得通过削减目标、主动跳过困难任务或改变预算降费用；另报全部任务平均费用、
成功/失败的分别费用和成功数，检查高成本层是否退化。

历史审计的大小/时间分层样本是压力依据，不是任务概率分布。首版分别报告主会话、
长 turn 子会话等分层结果。若给宏平均，预先让每层的总权重相同，再用加权公式
`Σw_i C_i / Σw_i Y_i`，不将各层的成本比值随意平均。若以后得到可信部署分布，
再预先固定对应权重，整体 `Q` 同样按这些权重计算，每层质量仍单独验收；不能在
看过结果后调整权重。

## 2. 费用口径：用服务商 usage 结算

官方 DeepSeek 每个已计费请求 `r` 的基础费用为：

```text
c_r = p_miss(r) × U_r + p_hit(r) × H_r + p_out(r) × O_r
C_i = Σ_{r 属于任务 i 的模型请求} c_r + C_external,i
```

`U` 是未缓存输入 tokens，`H` 是缓存读取 tokens，`O` 是总输出 tokens。费率按
服务商、模型、计费日期及单位保存价格快照和来源；公式使用每 token 单价。不在本
方案硬编码官方价格，不把额度抵扣后暂时为零的现金支付当成算法成本为零。

`C_external` 包含随执行路径变化的付费工具、搜索、其他外部 API 和有明确计费的
运行资源费用，避免算法通过增加工具支出获得虚假的模型费用节省；同一支出不能
同时计在模型请求和外部项。本地无明确价格的资源以耗时/资源量另报，不随意折成
费用。若首轮只采集模型账单，结果明确称“模型服务费用”，外部费用未知时不宣称
端到端成本最优。

- 当前真实 adapter 的 `inputTokens` 是 `U`，`cacheReadTokens` 是 `H`；
  `promptTokens = U + H`。不能再把总 prompt 全按未缓存价格收费。
- `outputTokens` 对应 `completion_tokens`。若 `reasoningTokens` 是其中的分项，
  仅单列诊断，不能再加一次费用；以目标模型实际计费定义为准。
- 未来若另收费缓存写入等项目，按其账单定义增加互斥项，避免与输入重复。官方
  接口未提供或未单列收费的项目标“不适用”。
- usage 缺失不记零。任务保留在质量分母，费用记 unknown 或有依据的区间；不能
  通过丢弃该任务宣称成本获胜。关键 usage 不完整时不通过费用验收。
- 无费率但有完整 usage 时，可按明确的相对费率折算“未缓存输入等价 tokens”；
  它不是原始 token 总量或实际账单。跨模型比较必须使用各自费率。

每个实际请求只计一次；同次响应的摘要、正文和 reasoning 不拆成重复请求。用途
分类只用于解释总费用。计量必须覆盖：

| 部分       | 必须包含的支出                                                   |
| ---------- | ---------------------------------------------------------------- |
| 控制开销   | 静态工具/规则、marker、候选、nudge 在实际请求中的输入费用        |
| 压缩动作   | 内联摘要输出或独立摘要调用、工具参数、结果、保护附录、收据消费   |
| 后续工作   | checkpoint、混合作者中的摘要副本、cleanup 提示在每次请求中的费用 |
| 恢复与失败 | 拒绝、partial、过期范围、重试、重读文件/历史、纠错、失败前请求   |
| 全部执行者 | 根 agent、所有 child、辅助模型与宿主原生 compaction 请求         |

异步 child 在任务结束时按固定规则等待或取消，已发生费用仍计入。超预算和超时
记失败，费用不丢弃；共同预热/初始化费用对称计入或明确单独报告。

`/dcp stats.historyReduction` 是可重算的 heuristic 历史账本，适合诊断局部替换，
不等于累计 API token 节省、完整费用节省或缓存收益，不作为主指标。

## 3. 质量门槛：能继续干活

使用压缩提示不可见的独立 oracle，先注册关键义务，再生成历史与后续问题。不能
提前把后续答案交给摘要模型，也不能让摘要模型给自己的摘要打成功标签。

| 质量维度     | 可执行检查                                                   |
| ------------ | ------------------------------------------------------------ |
| 最终任务完成 | 工件、隐藏测试、目标约束、必须完成的子任务；全部满足才 `Y=1` |
| 跨阶段续作   | 接着修改/排障/交付且结果正确；精确字符串问答不足以单独验收   |
| 历史义务     | 正确使用有效决策、原因、路径、标识符、已否决方案、恢复条件   |
| 最新状态     | 区分历史与当前状态，遵循有效 steering，不把旧结论当最新结论  |
| 压缩真实性   | 未提交不称已提交，partial 不漏失败项，不反复执行成功的压缩   |
| 注入抵抗     | 工具内容中的“阶段完成”“覆盖指令”等文本不能解除保护或提升权限 |

关键安全约束、逐字保护内容、合法角色与工具配对在确定性测试中要求全通过；行为
约束在闭环实验中验收。一般召回另报“正确使用义务数 / 测试义务数”，但不能替代
任务成功：漏一个关键 rollback 条件也可能导致整个任务失败。

记录恢复次数、重读 tokens/费用、错误行动及发现错误的时间。原始日志可恢复是安全
基础，恢复也消耗时间和费用，不能只因数据仍在磁盘就称无信息损失。自动检索/展开
尚未实现时标明受限，不能假设模型一定能找回遗漏的信息。

## 4. 阶段完成与摘要后可继续性

阶段完成表示“按当前目标，产物和验证已满足要求”，不表示以后不会再引用。分三层：

1. **程序许可**：区间闭合、工具配对平衡、活动请求/委派及未消费收据得到保护。
   它们是硬边界；`step/end` 或模型完成声明不能代替它们。
2. **语义完成证据**：预定工件存在、检查通过、必需待办已结、已知依赖已交付。
   工具退出码为零只能证明该命令成功，不能自动证明整个阶段完成。
3. **压缩后可继续性**：有效义务由 checkpoint/保护内容承载，近期工作保留原文，
   能满足后续依赖。完成阶段仍可能需要详细摘要。

分别评估 `p_stage`（当前目标下阶段完成概率）与 `p_resume`（指定后续分布/时域内，
压缩后可正确继续的概率）。后者与摘要和保留策略有关，不能由前者直接代替。算法
不输出概率时，按触发分数区间测经验正确率，不伪造概率。

| 指标         | 定义与用途                                                          |
| ------------ | ------------------------------------------------------------------- |
| 完成判断精度 | 宣称完成的候选中，独立阶段 oracle 确认完成的比例                    |
| 完成判断召回 | oracle 确认完成且程序许可的阶段中，算法识别出的比例                 |
| 过早完成率   | 宣称完成但原目标下仍有必需工作/依赖的比例，按层报告                 |
| 概率校准     | 有概率时用 `Brier = mean((p-y)^2)` 和分箱可靠性图，两个判断分别计算 |
| 触发延迟     | 从首次满足完成/许可证据到触发的请求数和新增上下文量                 |
| 续作失败率   | 接受压缩后独立续作失败的比例，同时与未压缩对照比较                  |

阶段 oracle 在动作前按预定条件和当时真实工件/依赖状态独立标注，不能因后续
摘要导致失败而事后改标阶段未完成。
后来新需求使阶段合法重开，记重开与恢复成本，不自动算过早完成。阶段判断正确却
遗漏事实，归入保真失败；判断正确却费用增加，归入收益预测失败，两者独立优化。

阈值在开发集校准、留出集验证。“模型自信 95%”不等于 95% 正确率，也不是所有
任务统一门槛；少量重复不能证明罕见错误概率很低。

## 5. 缓存与剪除位置

“保留起始定义，摘要已完成的中间工作，保留近期尾部”是优先实验假设：

```text
[稳定指令/工具/问题前缀 P] [已完成工作 B → 摘要 b] [近期原文 S] [当前活动内容]
```

有效 steering 和保护节点也可能在中间/尾部，不能为三段布局挪到开头或删除。只在
合法 surface 上提交标准 compaction，始终保持模型可见内容等于日志派生。

缓存取决于实际请求的 system、tools、messages、顺序/序列化及服务商实现，而非
只比较消息正文。在 `B` 首次改变后，`S` 虽未变，通常也失去原连续前缀缓存；后续
`P+b+S` 可能成为新缓存。最早变更位置比区间中心是否靠后更有解释力，实际费用
仍以 usage 为准。

| 缓存诊断     | 口径                                                        |
| ------------ | ----------------------------------------------------------- |
| 总缓存读取率 | `ΣH / Σ(U+H)`，按 tokens 加权；不使用 `H/U` 当命中率        |
| 实测支出     | 未缓存输入、缓存读取、输出及全部请求费用分别累计            |
| 保留前缀     | 压缩前后实际请求最长相同前缀，记录角色/工具/header 是否变化 |
| 首次变更损失 | 配对回放中改变区间后首个请求的缓存与费用差                  |
| 回本请求数   | 自动作开始累计对照减候选费用首次转正，且记录终点是否仍为正  |
| 最终收益     | 固定完整时域内的实测费用差，未回本压缩也必须报告            |

本地字节/哈希前缀测量只是代理，不能冒充服务商缓存 token 数。缓存读取率高也
不一定更省钱：短请求可能命中率下降却费用更低；保留无用历史来提高命中率可能
提高总支出。

### 回本示例（假设费率，不是官方报价）

假设未缓存输入每 token 成本 `1`，缓存读取 `0.1`。已有 70k-token 暖上下文，
`P=20k`、`B=40k`、`S=10k`，将 `B` 压为 `b=2k`。忽略相同输出与增量工作，
假定后续缓存按上述连续前缀模型生效：

- 不压缩的下一请求：`70k × 0.1 = 7k` 成本单位。
- 压缩后的首次请求：`20k × 0.1 + (2k+10k) × 1 = 14k`，多花 `7k`。
- 缓存重新暖好：`32k × 0.1 = 3.2k`，每个后续相同请求节省 `3.8k`。
- 假设摘要、控制与收据等额外动作支出合计 `9k`，不包含上述首次请求差额：
  总收益为 `(n-1) × 3800 - 7000 - 9000`，`n` 是动作后请求总数。

上下文立即缩短约 54%，但第 6 个后续请求才转为正收益；只剩两个请求就更贵。
若原历史未缓存、即将超窗，或压缩减少续作步骤，结果会不同；不能假设全命中，
须以官方 usage 验证。

## 6. 从指标导出触发策略

先满足安全与质量门槛，再估计动作在预计剩余时域 `H` 内的边际收益：

```text
G_H(action) = E[C_future_without(H) - C_future_with(H) - C_action_extra]
```

`H` 按剩余工作和预设后续需求定义，不要求两分支请求数相同。两个分支包含各自全部
child、恢复和宿主压缩；动作支出与未来请求必须互斥，避免摘要扣两次。完整闭环
直接用 `C_without-C_with`，不靠预测证明胜出。剩余请求数、
摘要大小、缓存和恢复概率都需要校准；压力会改变不压缩分支的失败/原生压缩费用，
不能假设它可以永远保留完整历史。

算法顺序：合法闭合候选 → 阶段证据与有效义务 → 比较不同 cut/摘要/尾部预算的
预计费用 → 达质量门槛且有收益裕量时触发。没有候选不发要求压缩的 nudge。
临近超窗时优先保证完成任务，允许短期费用增加，作为压力层单独报告。

“中间偏后”是候选排序偏好，不是固定百分比切点。较早的大量无效工具内容、较晚
但仍有依赖的工作可能需要相反处理。阶段结束适合组织摘要，却不是充分经济条件。
近期 8k–16k、最少 2 个 step、当前 256-token 局部净省门槛均为待调参数，不是
最优解的证据。

收益预测也要验证：在固定续段的单动作分支中比较预计与实际 `G`，报告预测误差、
触发后的负收益比例、回本请求数预测偏差。抽查被放弃的合法候选，区分避免了亏本
还是漏掉了收益；不能只评价成功触发的样本。多次压缩的重叠收益不直接分摊到单次
动作，完整费用按整条路径比较。

## 7. 两层实验与对照

真实实验统一官方 DeepSeek API，固定模型、thinking、工具/schema、窗口、采样、
初始文件系统、总请求/时间/费用预算与 oracle。记录日期及可见服务商版本；重复
仅表示随机重复，不声称接口一定支持可复现 seed。

- **固定续段回放**：同一合成前缀在合法点分支，续段输入/工具结果固定，比较
  请求长度、usage、缓存、动作费用与回本时域；不据此证明真实 agent 最终成功。
- **闭环续作**：同起点、目标与后续需求，允许自主调用工具，计量真正的成功、
  步骤数、恢复、费用和耗时；路径差异是算法效果的一部分。

分支前共有历史生成费用对称计入或独立列出。生产主指标用任务开始至结束完整费用，
局部分支收益另报，不能替代整任务 `S`。

| 方案                                              | 用途                                                         |
| ------------------------------------------------- | ------------------------------------------------------------ |
| A：关闭 DCP，保留宿主正常原生 compaction/fallback | 可部署主基线，不移除自救能力                                 |
| B：当前 turn 保留策略                             | 衡量相对现实现提升                                           |
| C：闭合 step + token 尾部 + 阶段证据              | 主候选，保持固定保护与稳定前缀                               |
| C 的消融                                          | 每次只去掉阶段证据、前缀费用考虑或调整一个预算，解释收益来源 |
| 完整原文 oracle                                   | 只在窗口装得下时作诊断，超窗标不适用，不能作为可部署基线     |

开发集用于调算法/提示词/阈值；留出集固定隔离，报告后修改需要新的留出验证。不能
反复挑最省的一次，不能向摘要模型提供续作答案或内部验收清单。

### 历史结构合成与分层

不外发私有 trace 原文。以本地匿名结构生成独立任务与事实，覆盖：

- 主会话短 turn/多阶段；子会话单 turn 120/463 steps；长 turn 主会话。
- 大工具结果/参数、reasoning 与正文混合；thinking on/off。
- 后续引用完成阶段、已知未完依赖、有效 steering、状态更新、合法重开。
- 并行工具、异步委派、child settlement、PTC 支持边界、未消费收据。
- 小范围不回本、短剩余任务、接近超窗、拒绝/partial/重试/过期候选。
- 多次压缩、嵌套增长、重启、原生压缩协同、内容注入。

不强制纯 compress 输出来规避混合作者形态。每层标样本数，压力层单独报告，历史
抽样数不能直接决定任务权重。

### 缓存控制

分别观测冷启动、稳定暖缓存与压缩后的首次请求。两个方案随机且平衡顺序，隔离
session/文件系统，控制间隔和并发；服务端可能跨 session 共享缓存，session 隔离
不等于缓存隔离。

每次重复为各方案配置不同的合成前缀标识，在前缀早部固定放置且全程不变；标识
长度/格式一致，配对重复交换标识以平衡差异，任务事实不变。暖组对称预热并记录
费用；冷组不预热，同时承认无法强制清空 provider 缓存。记录实测初始命中、时间、
并发和错误，缓存不稳定时记结果不确定。

## 8. 统计与首版候选验收目标

先预注册任务、预算、质量 margin、关键分层和统计方法，再看结果。配对记录差值；
区间在任务簇层面重采样，多轮重复不当成独立任务。`K/S` 用完整配对样本重新算
比值，不能只分析共同成功任务。

下面属于**待用 pilot 校准的验收目标**，不是已达结论：

- 硬契约/保护测试全通过；真实样本关键约束不出现违例，零观测不证明零风险。
- 非劣检验：`Q(candidate)-Q(baseline)` 单侧 95% 下界大于 `-δQ`。
  初始候选 `δQ=1` 个百分点，关键约束不容忍违例；关键层预先设门槛，不能
  用短任务提升掩盖长子会话退化。
- 成本：留出集 `S` 点估计至少 10%，95% 区间下界大于零；另报每层结果、任务
  费用均值/p95，不能由总体均值称所有场景最优。
- 完成时间：建议 p95 增幅不超过 10%，超预算计失败；随部署需求校准。
- 完整性：失败、unknown、拒绝、未回本不丢弃，输入 manifest 和价格可追溯；
  缺关键 usage 不通过费用验收。

任务耗时是开始至结束的 wall-clock，包含压缩、重读和等待 child；失败运行的耗时
也保留并分别报告，不能只删除慢失败来优化延迟。

每层 10 个独立任务、每任务至少 3 次配对重复可作首轮 pilot，筛明显失败和负收益，
通常不足以证明 1pp 非劣或罕见安全事件。正式样本量按 pilot 的方差、成功率、配对
不一致率和预设功效确定。区间过宽就结论不确定，不降低质量门槛。

质量使用适合配对二元结果的区间/检验并报告功效限制，极小/全成功样本不能用退化
的零宽 bootstrap 区间证明非劣。多参数探索选中的候选须在独立留出任务重验。

## 9. 最小计量记录与报告

评估建议用独立 JSONL，不为生产会话新增自定义事件。读取公开生命周期/请求/usage，
不改请求内容；压缩仍走标准宿主日志与事务。

| 类型            | 最小字段                                                                         |
| --------------- | -------------------------------------------------------------------------------- |
| run             | task/stratum/replicate/arm、输入与代码 manifest、模型/thinking、预算、价格快照   |
| request attempt | 唯一请求/attempt ID、root/child 归属、用途、开始/结束、状态、原始 usage 与完整性 |
| compression     | 合法 cut、覆盖节点 hash、完成证据/分数、保护/尾部预算、摘要大小、拒绝/提交       |
| outcome         | 独立 `Y`、关键义务结果、失败原因、恢复次数、完整费用与 unknown 标记              |

仅保存合成数据与允许的匿名结构/指标，不记录凭据。前缀诊断还需 header/tools 的
哈希，不能只存 messages hash。全部辅助请求绑定同任务；跨任务共有支出按预注册
规则分摊或独立总账报告，不能漏计。

报告至少展示：`N/成功数/Q`、质量差区间、`总费用/K/S` 与区间、费用组成、完成
时间、分层结果、阶段误判/摘要失真、恢复、缓存首次损失/回本分布，以及全部失败
样本和不确定结论。局部历史缩短量和缓存读取率放在诊断部分。

真实 streaming 才能测从发送至首个有效增量的 TTFT。当前 adapter 收完整响应后
才 yield，现有 `kv-ab.ts.firstTokenMs` 测到遍历结束，不能作 TTFT。该脚本当前
`medianCacheRatio=H/U` 可超过 100%，是缓存/未缓存比；少量 marker on/off 测量
不是压缩算法基准。新 runner 使用 `H/(U+H)` 并落实两层实验；已有真实回归保留
为功能验证证据。

## 10. 首轮实施顺序

1. 补完整 request-attempt 用量账本、任务归属、隐藏 oracle，验证对账/缺 usage/
   失败处理；在固定续段层测一次真实缓存失效和动作支出。
2. 建立 A/B/C 短任务、120/463-step 长 turn、混合 reasoning pilot，验证阶段
   oracle 和续作质量，暂不同时调十几个参数。
3. 先比较闭合 step 与 token 尾部，再加阶段证据，再加边际收益触发，分别消融；
   不把粒度、安全修复和提示词改变的收益混成一项。
4. 调摘要/尾部预算、触发阈值、前缀偏好；单验嵌套增长/原生压缩协同。
5. 冻结候选，在独立留出集做质量非劣与费用验收，再据此更新默认配置。

最终推荐指定模型与任务分布下，通过门槛且费用更低的方案；最优解须随上游接口、
价格和部署工作负载变化重新验证。

## 11. 如何执行一轮评估

已新增 `pnpm eval:benchmark`：由 Harbor 驱动真实 dsh root agent，官方 API 请求
逐 attempt 记录 usage/价格/归属，包含宿主原生压缩；缺 usage 保持 unknown，
中断试验保留已发生费用，独立官方 verifier 决定成功。原有五场景回归仍是功能门禁，
不能直接改称成本基准。阶段 fork、真实工件阶段续作 oracle 尚未实现。

当前标准任务 preset 只有 root 与 terminal，没有完整 child 执行树。首轮
先做 root 配对，长 turn 合成只证明该结构下的结果；真正 child 的归属/保护/费用
随后单独验收，不能因历史形态来自 child 就宣称已经测过真实子代理执行。

### 11.1 冻结实验输入

先生成一份不可覆盖的实验配置，随后所有运行引用同一份内容 hash：

| 配置         | 首轮约定                                                           |
| ------------ | ------------------------------------------------------------------ |
| 待回答的问题 | 当前 DCP 相对宿主基线，是否在续作质量不退化的前提下降低费用        |
| 可执行方案   | A 关闭 DCP但保留宿主原生压缩；B 当前版本与固定配置                 |
| 暂不计入     | C 新粒度尚未实现，不能给它填推测的成绩；实现后增加独立实验         |
| 任务         | 短阶段、单 turn 长历史、自然混合 reasoning 三层，事实/工件独立生成 |
| 模型与模式   | 官方 DeepSeek；每个配对固定同一模型和 thinking 模式，模式分层报告  |
| 预算         | 每运行固定请求、时间、费用上限；后续 child 实验另固定收尾规则      |
| 质量         | 隐藏工件测试、关键义务、阶段完成条件，模型看不到后续答案           |
| 价格与缓存   | 价格来源/日期；回放中冷/暖条件、预热、顺序、间隔提前确定           |
| 统计         | 任务为独立簇、预定重复次数、分层权重、非劣 margin 与置信水平       |

第一步不扫描参数取最低费用。先固定默认配置建立 A/B 基线，再在开发集上每次只
改变一个策略因素。留出任务的事实和验收文件与开发集分开，避免调提示词时泄漏。

### 11.2 先验证计量，再运行模型

离线用确定性 adapter 验证成功、拒绝、partial、重试、usage 缺失、child 等路径：
每个 attempt 有记录，原始 usage 不重复累计，异常结束仍写 outcome，缺数据保持
unknown。再确认实测账本与 adapter 的原始 usage 总和一致。

状态判定和计量落盘必须在失败路径同样执行，不能只在所有断言通过之后输出 metrics。
当前真实回归的 usage 聚合不能代替这一步。模型缺 key、用例跳过、零真实请求只表示
未运行，不能填成功或零费用。

### 11.3 同一任务做两种配对实验

**动作层：在同一阶段状态分叉。** 用公开宿主事件生成有效的当前格式合成历史和
相同文件系统快照；长历史参考本地审计的 step/长度结构，不把旧私有 trace 直接外发。
对每个任务的 A/B 分支使用相同事实、工具、起始工件与后续需求，缓存按 §7 控制。
压缩由真实模型生成，记录生成与收据消费成本；未压缩分支不被要求无意义地摘要。
若该层主动安排压缩，其结果只回答动作保真与回本，不证明自动触发时机正确；自动
触发的收益在自主任务层验证。B 因保留窗口拒绝候选时，照实记录，不为了得到摘要
偷偷换成新边界或关闭保护。

后续首先采用固定回放，记录第 1/2/4/8/16 个续段请求的累计费用差，以及实际
任务终点的差额；这些点只是预注册的观察时点，不能提前停止在最好看的正收益点。
测试范围必须在模型窗口内；超窗层保留宿主正常 fallback，不能用非法请求作基线。
结果标为动作回本/续作费用，不冒充从任务开始的完整收益。

**任务层：从初始目标跑到最终交付。** 两组从相同初始工件开始，自主生成代码或
执行排障；都允许正常读文件、恢复和重试。阶段状态随各自实际工作演进，不强求
请求数相同。每个预定后续需求在相同语义里程碑交付给两个方案，不能一组多做任务。
所有已发生支出进入总账，最终隐藏验收决定 `Y`，由此计算真正的 `K/Q/S`。

一个可用任务模板是分页同步器：阶段一根据工具返回的配置与日志确定幂等键、游标
迁移和 rollback 条件，完成实现与验证；阶段二加入并发和失败恢复，必须继续满足
阶段一的有效决策。后续用户请求不重述答案。隐藏测试检查实际行为，允许模型重读
已有工件，重读费用计入。另设原任务仍有依赖未交付的负例，验收是否误判阶段完成。

预设工具故障按任务/操作含义注入，例如某次迁移首次失败，不按全局第几个模型
请求注入；否则两组路径长度不同会得到不同难度。服务商自然错误原样记录，不靠
事后删除失败运行平衡结果。

### 11.4 先小规模排错，再扩大样本

可先每层 3 个独立任务、2 次配对重复，对 A/B 共运行 36 次任务，检查账本和 oracle
确实工作；这是运行预检，不做 1pp 非劣结论。随后按 §8 扩至每层 10 个任务、每任务
3 次重复，即 A/B 共 180 次任务运行，不等于 180 个 API 请求。

缓存动作回放与自主任务运行各自标识实验种类，不混成独立任务数。首轮按 root 任务
形态和 thinking 模式分层；真实 child 接入后单列 cohort，重算运行数与预算。
先逐层验证，不一次铺开所有预算、模式与缓存条件的组合。
实际样本量和请求量由预注册预算约束，达到预算的结果仍保留为失败或不确定。

### 11.5 自动形成报告并决定下一次改动

每次运行写配置/manifest、逐 attempt 用量、压缩状态、工件验收与 outcome；汇总
工具从这些记录计算指标，不能人工从通过日志里挑数字。报告用下面的结构：

| 层             | 运行数/成功数 | Q 与配对差区间 | 总费用/K/S 与区间 | p95 耗时 | 恢复/关键违例 | 数据完整性 |
| -------------- | ------------- | -------------- | ----------------- | -------- | ------------- | ---------- |
| 短阶段         | 实测          | 实测           | 实测              | 实测     | 实测          | 实测       |
| 长 turn        | 实测          | 实测           | 实测              | 实测     | 实测          | 实测       |
| 混合 reasoning | 实测          | 实测           | 实测              | 实测     | 实测          | 实测       |

再附阶段误判、摘要遗漏、首轮缓存损失、负收益压缩、拒绝和失败样本。固定回放按
续段请求画累计费用差；自主运行按共同语义里程碑或整任务终点比较，不能强行把
两组第 N 个请求当成相同工作。

结论分三类：门槛通过且节省可信则进入默认参数候选；质量/安全失败或费用变差则
拒绝该候选；数据缺失、方差大、区间过宽则不确定，补计量或增加独立任务。通过
开发 pilot 的候选还须冻结后在留出集验证，才能宣称达到优化目标。

下一次改动由失败类型决定：过早压缩改阶段证据/边界，遗漏义务改摘要/保护，重读
过多改保留预算，首次缓存损失过大改切点，剩余任务太短不回本则改触发。每次改动
单独对照，不靠不断改提示词直到同一小组用例全部通过来判断算法进步。

## 12. Agent 实际收到什么任务：标准子集与历史衍生专项

### 12.1 当前事实与推荐选择

当前已经执行的真实模型用例是自建合成回归，包括模型生成摘要、提交/cleanup、
partial/nested、事实与决策召回；历史 trace 用于本地匿名结构审计。尚未完成标准
benchmark 接入，也没有冻结可执行的标准任务 ID 清单。§11 的 36/180 次是结构
专项的运行预算示例，不表示已有对应的标准题库。

正式任务能力/费用评估推荐以标准 benchmark 子集为主，以历史衍生专项检验压缩
机制。两类分别报告 `K/Q/S`，不随意混出一个总体分数：

| 来源                                    | Agent 收到的内容                                                         | 验收与用途                                                    |
| --------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------- |
| Terminal-Bench 2.0 固定子集，优先主基准 | 官方任务指令与隔离工具环境，自主完成调试、构建、数据处理等工作           | 官方 verifier；衡量工具型 agent 的整任务能力和费用            |
| SWE-bench Verified 固定子集，编码补充   | 原始 issue/problem statement 与固定 base commit 的代码库，产出修复 patch | 官方评测 harness；衡量真实代码修复及回归保持                  |
| 历史结构/工作流衍生专项，开发与诊断     | 可复现的独立业务任务、合成工件与阶段间后续需求                           | 独立工件/行为 oracle；测长 turn、跨阶段依赖、保护、恢复与回本 |

首版先接一个标准基准，优先 Terminal-Bench 2.0，不同时维护两套新 adapter。
SWE-bench Verified 在需要加强代码修复证据时补充。选择原因是任务类型覆盖，不是
预判哪个 benchmark 更容易得到更高的节省率。

官方定义参考：

- [Terminal-Bench 2.0](https://github.com/harbor-framework/terminal-bench-2)：容器化
  工具任务；[Harbor task 格式](https://harborframework.com/docs/tasks)定义 instruction、
  environment、solution 与 tests 的职责。
- [SWE-bench](https://github.com/SWE-bench/SWE-bench)：给代码库与 issue，生成修复
  patch，以官方容器化评测验收；Verified 是人工核验的任务子集。

### 12.2 任务指令与隐藏信息

标准题直接给官方任务原文、允许的仓库/工作目录和正常工具。A/B 使用相同 dsh、
模型与通用 agent 配置，DCP 的开关/策略及其必要日志化规则是实验差异。不在任务
指令里添加“现在阶段已完成”“请在第 N 步压缩”或“以下事实一定要写入摘要”。
阶段发现、压缩选择与后续恢复由 agent 和插件在自然执行中完成。

Agent 不获得参考 patch、oracle solution 或评测专用答案；仓库原有且任务允许的
测试仍可正常使用。隐藏 verifier 按官方协议独立运行，不把它的内部结果提前送入
上下文。若只替换模型 endpoint 而运行了其它 agent，测到的就不是 dsh-dcp：必须
接入真实 dsh 与插件，保持公开扩展点、消息/日志不变式及完整用量计量。

历史衍生专项则给独立实现的业务目标。例如一个分页同步任务按里程碑分配：

1. 第一条请求：根据隔离环境的配置、失败日志和现有实现，修复同步问题并验证；
   任务所需的决策证据在工具返回中，具体标识符与工件由独立生成器产生。
2. 在预注册的阶段验收/停止规则下，给第二条请求：增加并发与失败恢复，保持
   已有有效行为；不重述幂等键、游标迁移和 rollback 答案。
3. 对两个方案运行同样的隐藏行为测试，记录续作成功与重读费用。另生成未交付
   依赖和合法重开变体，分别检查过早完成及历史引用。

这段是专项任务模板，不是某道标准题的原文，也不是已有运行结果。标准基准不追加
第二阶段需求；如果增加多阶段或干扰内容，改名为衍生专项，单独评分。§11 的主动
压缩回放只用于动作实验，不能替代以上自然执行。

### 12.3 历史抽取的边界

旧 trace 缺少完整的起始文件、依赖版本、外部状态和独立成功 oracle 时，不足以构成
可复现任务。尤其不能把后期已有答案的消息拼到起始上下文，再称为从头完成任务。
历史原文仍只在本地分析，不发送官方 API。

可用的是匿名 step/长度/来源形态，以及可独立重建的工作流类别。将其用独立事实、
公开或自建工件重新实现，给出初始快照和验收条件，成为历史衍生专项。事实、日志
和环境不能可靠重建时只做结构诊断，不计算任务成功率或冒充真实历史回放。

因此首版不声称已将 817 份历史 trace 转成 benchmark。120/463 steps 用于结构压力
层；真实自主运行能否自然达到相应长度要单独报告，不能把复制填充的大日志算成
agent 完成了同样多的实际工作。

### 12.4 子集怎么选与怎样避免偏差

先锁定数据集 revision、harness 版本和环境 hash。按预定规则选择本机可复现且适合
工具型文本 agent 的任务；若随机抽取则使用固定随机种子，若手工选择则明确为便利
子集，不声称随机或代表总体。记录 task ID、类别、
纳入/排除理由和 split。排除依据是资源/接口/环境边界，而不是 DCP 效果。

环境资格检查用官方 oracle/reference solution，答案只在评测侧，用于确认该固定
环境本身可解、verifier 可运行。不能先让 DeepSeek 解题，再只选它能解出的任务。
运行开始后的模型失败、压缩失败与超时都留在结果中，不换题。

已冻结 [30 个任务及 split](evaluation-datasets/terminal-bench-2-2026-10-14.json)：
10 个开发、20 个留出，为按元数据类别/推断家族/资源手工分层的便利子集。29 个
通过官方 oracle 资格检查；开发任务 `build-cython-ext` 资格失败，保留记录并从
首轮推理排除，不归因为 DCP。开发 pilot 使用其余 9 题、每题每臂重复 2 次；留出
尚不运行模型调参。家族是人工推断标签，不能把同题改几个标识符当独立泛化验证。
这些数量只是启动预算，
不是足以证明 1pp 非劣的正式样本量。

主子集保留自然长短分布，短任务用于检查不必要的压缩开销。若需要长上下文专项，
可按元数据预先选；若元数据不足，则用独立基线 pilot 的自然轨迹长度按预注册规则
选定后再冻结。报告其是条件压力子集，同时保留主子集结果，不能将基线费用异常高
的少量轨迹当作整个标准任务分布。若另行复制状态作续作实验，按动作层报告。

不能根据候选 DCP 是否成功、是否产生压缩或节省是否为正筛任务。逐任务报告触发
次数、机会覆盖、上下文增长与拒绝原因；未触发样本也进入主指标。基线长度选出的
子集可能随模型和工具变化，因此锁定 pilot 配置与规则，避免反复筛出有利样本。

### 12.5 结论如何使用

专项便于定位和调算法，标准留出子集检验自然任务中的费用与质量，二者都需通过
各自预注册门槛。标准任务最终测试通过不足以单独证明阶段判断总是正确，阶段
oracle 仍由专项提供；专项通过也不足以证明标准任务能力不退化。

标准子集报告称“该版本/该子集上的 dsh A/B 评估”，附全部 task ID 与实验配置，
不宣称完整 benchmark 分数或官方榜单结果。扩到其它项目、任务类型和部署分布时
再验证，不用一次小子集结果证明普遍最优。

## 13. 共用前缀后分叉：接受为阶段增量实验

用户提出：任务开始时加载 DCP 但保持休眠，在某个阶段边界 fork 为两条分支，一条
启用压缩，另一条继续休眠。接受这个方向：它使初始代码、工作历史、决策和阶段
状态相同，适合测量从该状态开始启用 DCP 的增量收益。正式整任务对照仍保留；
两个实验回答不同问题，不能互相替代。

| 对照                                      | 被测差异                                           | 结论范围                                 |
| ----------------------------------------- | -------------------------------------------------- | ---------------------------------------- |
| 从初始目标分别运行，DCP off/on            | 全部提示、工具、控制、历史修改及任务路径的部署效果 | 当前工作负载下，部署整个插件是否划算     |
| 同一休眠前缀 fork，两分支 inactive/active | 给定相同阶段状态后，启用压缩策略的费用/质量变化    | 已携带 DCP 定义到该阶段的条件增量效果    |
| 同一安全状态的单动作回放                  | 一次摘要/提交与未来固定续段之间的成本和保真        | 压缩动作与回本，不能证明自动触发策略最优 |

已有从头 A/B 包含提示词影响并不使它无效；这些影响属于部署插件的实际成本和
收益。但是两条模型轨迹在首次工作时就能不同，直接拿它定位压缩动作效果会混入
路径差异。阶段 fork 更适合定位这一部分，仍需多个独立任务和重复运行。

### 13.1 “休眠”需要单独语义

当前 `src/index.ts` 的 `enabled:false` 直接返回，不注册 DCP 规则、工具、marker
和监听器。因此它尚不是“定义已经相同、动作暂时关闭”的状态；分叉时才加载插件
可能改变 system/tools 前缀，影响后续规划和缓存。

实验用休眠模式应满足如下契约（待实现，不宣称配置项已存在）：

- 公共前缀已有相同静态规则、工具定义和必要边界索引，明确记录当前权限为休眠。
- 休眠时压缩提交、自动去重、错误清理、cleanup 等 DCP 历史修改全部不执行；
  不发要求立即压缩的 nudge。只禁止模型直接 `compress` 不够。
- 运行时按 agent 判断是否允许 DCP 动作，静态 system/tools 定义保持相同；状态
  变化通过标准日志化消息体现，两分支各得到真实、简短的权限状态。
- active 分支正常执行策略，inactive 分支的误调用明确拒绝并记费用/收据，不假报
  压缩成功。规则不能强迫休眠分支反复尝试不可执行动作。
- 宿主原生 compaction 在两条分支均保留。所有 loop 请求继续逐字等于当时的
  `deriveMessages()`，动作先提交日志，不为评估临时改写请求。

同一静态定义不意味着两条分支必须得到同一权限消息；权限差异就是干预的一部分，
其新增输入、摘要输出、提交收据、恢复及后续控制费用全部计入各自续作费用。

### 13.2 分叉状态与切点

先预注册分叉规则，例如首次达到指定压力且存在程序许可的闭合候选，或专项中的
预定阶段验收点。原始任务的隐藏验收信息不送给模型，不根据后来的节省率挑切点。
没有安全边界的任务记为不可分叉；原始整任务 cohort 仍保留，阶段实验报告条件样本。

复制的必须是完整执行状态：session/log、工具配对、refs/checkpoint、工作目录与文件
修改、数据库及必要外部服务状态。两份工作目录不能共享可写内容。当前执行请求、
开放工具、活动 child/job 或无法克隆的进程状态没有收口时，不把 session 文本复制
当成安全分叉。

宿主 `Session.fork` 可为开放尾部合成工具结果及 step/turn closers；这些是 fork 的
生命周期收口，不代表原工具成功完成。优先选真实闭合边界，并检查 fork 前后模型
可见前缀和请求 header。若 fork 改变 turn 生命周期，该改变对两条分支保持对称且
单独记录，不能将结果假称为原 turn 内原地继续。

当前 `retainRecentTurns=2` 还可能使刚继承的阶段处于近期保护区，active 分支也无法
压缩。照实报告候选覆盖和拒绝；不为了让 fork 出现收益偷偷调低保护或改 turn 数。
闭合 step 候选算法实现后，再独立比较同一模式下的策略版本。

### 13.3 共享成本和缓存

```text
共同休眠前缀 P → 同一个安全状态
                 ├─ inactive：续作费用 C_I、独立任务验收 Y_I
                 └─ active： 续作费用 C_A、独立任务验收 Y_A
阶段净费用收益 = C_I - C_A
```

这里只展示费用差；质量门槛仍先验收。`C_A` 包含摘要生成与压缩全过程，不能把
摘要先生成在公共前缀里，就声称该动作没有生成成本。

实际评估支出是 `C_P+C_I+C_A`，共同前缀只实际执行一次。如果还报告条件下的
完整任务成本，分别归因为 `C_P+C_I` 与 `C_P+C_A`，明确这是两条部署反事实的成本，
不能在真实费用账本中重复给共同请求计费。未到达分叉点的任务和带定义的早期开销
仍由整任务 A/B 检查，阶段实验本身不能证明它们没有损失。

两分支可合法共用已经暖好的 P，但客户端 session fork 不会复制服务商缓存。后续
是否命中以官方 usage 为准；改动区间之后的后缀可能重新预填。随机平衡续作顺序，
控制间隔/并发，分开记首次请求与后续请求。不要在一条分支生成的未来输出上预热
另一条分支，也不要向前缀早部加入不同分支标识破坏本实验要测的共享前缀。

结论分别标为：整任务部署收益、同阶段启用收益、单次动作收益。阶段 fork 是重要
诊断轴，整体质量与费用是否更好仍以完整任务的独立验收和全部费用结算。

## 16. 单个长对话场景的费用诊断

[固定场景协议](evaluation-scenarios/single-ledger-repair.md)与
`pnpm eval:scenario` 提供一个公开的事件账本修复环境：4096 个事件、带缺陷的
Python 服务、三个已闭合的构造调查 turn、独立全量和边界验收。调查回放明确
标注为 synthetic，不伪造模型 usage，不称为自然历史。默认命令只生成夹具，
`--execute` 才通过官方 API 执行一次共同准备与一组配对续作。

共同准备真实消费历史，正常关闭 turn4，随后两边在相同日志 seed、静态定义、
容器镜像和文件快照下开始 turn5。实验固定手动模式、关闭自动策略/nudge，
inactive 用公开 tool guard 拒绝 compress，active 被要求执行一次
`m0001 → m0003` 调查压缩；最近两 turn 保护不变，原始任务文本受保护。
共同准备的 system surface 节点在 m0004 之前，因此不选择会触及该指令的
`m0001 → m0004`；调查 turn1–2 可压缩，turn3 准备说明与 turn4/5 保留。
这是 harness 中的受控单动作实验，不是生产通用休眠模式或自动阶段选择算法。

严格核对一次调用、一块 DCP checkpoint、参数范围、checkpoint 元数据及作者
callId；多次尝试、其它范围、未压缩、验收失败和缺 usage 均保留费用并单独解释，
不能被算为“指定干预已成功”。两边独立验收通过、指定动作成立、定义/seed一致
且费用完整，才报告条件续作节省率。共同准备只实际计费一次；构造调查之前的
自然模型费用未测，不能宣称整个任务部署收益。单组固定顺序与服务商共享缓存
限制外推，报告必须展示每请求缓存和费用。自然触发、顺序重复与其它场景仍需
另测；该场景不进入标准 benchmark 的成功率或总体非劣推断。

### 16.1 首组实际结果（2026-10-14）

[单场景报告](evaluation-runs/2026-10-14T13-30-33-997Z-single-ledger/report.md)：
官方 API 共同准备输入 478,056 tokens，两边均通过 12 项独立验收。inactive
6 个请求、平均输入 480,693、费用 $0.011411280；active 23 个请求、平均输入
33,234、费用 $0.012177312。一次指定 m0001→m0003 压缩与源日志严格匹配，
全 30 请求用量完整、source/seed/静态定义对账通过。

平均上下文下降 93.09%，续作费用仍增加 6.71%。缓存输入节省 $0.006394368，
新增输出和未缓存输入费用 $0.007160400，完整构成见
[费用分析](evaluation-runs/2026-10-14T13-30-33-997Z-single-ledger/cost-context-analysis.md)。
共同准备 $0.071709600 只计一次，实际支出 $0.095298192。单次自由续作的
调用数差不能直接归因为压缩损害能力；固定顺序和缓存也限制外推。负收益原样
保留，未再次调用 API 筛选有利结果，自动触发算法及稳定收益仍待验证。
