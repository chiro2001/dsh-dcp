# 单场景的上下文与费用对账

本次指定阶段压缩成功，两边各通过 12 项独立验收，但续作费用增加 **6.71%**。
平均上下文下降 **93.09%** 并没有变成净费用节省：更多调用和输出抵消了缓存
输入节省。这是一个固定场景的一组实际观察，不能证明压缩必然导致更多调用。

## 固定状态与口径

公共准备真实消费 478,056-token 构造调查历史并闭合。两边继承相同完整 seed、
静态 system/tools、固定 Docker image 和四份文件的独立副本。实际任务是修复
事件账本、重放 4096 条事件、写出正确结果；初始代码无法通过公开 smoke。
原始 input/spec/smoke 保持不变，完整账本与边界探针独立验收。

构造回放标明 synthetic，没有伪造此前 API usage；自然调查生成费用未测。
干预为一次指定 `m0001 → m0003` 压缩，调用参数与 DCP checkpoint 的范围和
callId 全部一致。没有非 DCP 摘要或 compaction-purpose 请求。所有 30 次实际
API 请求用量完整、响应正常，HTTP 重试或未知费用没有造成此处差异。

active 的第一请求仍消费完整历史（478,197 tokens），用于生成并提交压缩。
紧接的请求降至 3,558 tokens；其后 22 个请求平均 13,007.95 tokens，随着代码
修改、验证和结果继续积累，最后一次输入为 21,767。全续作平均包含首次压缩

请求，因此 p95 低于均值；这只是该运行内分位数，不是总体性能估计。

平均输入下降 93.09%，累计输入下降 73.50%；每请求平均费用下降 72.16%，
但请求数为另一分支的 3.83 倍、输出为 3.14 倍。最终费用须保留完整续作直到
独立验收，不能截取尚未完成的较便宜前半段。

## 费用为什么增加

按每个请求冻结的官方 usage 与价格分别计费，本轮均为 off-peak：未缓存输入
$0.15/百万 tokens、缓存读取 $0.003/百万、输出 $0.60/百万。reasoning 为零。

| 费用组成   |     inactive |       active | active − inactive |
| ---------- | -----------: | -----------: | ----------------: |
| 未缓存输入 | $0.000239400 | $0.001990200 |     +$0.001750800 |
| 缓存读取   | $0.008647680 | $0.002253312 |     −$0.006394368 |
| 输出       | $0.002524200 | $0.007933800 |     +$0.005409600 |
| 合计       | $0.011411280 | $0.012177312 | **+$0.000766032** |

减少 2,131,456 个缓存读取 tokens 只省下 $0.006394368；多出的 9,016 个输出
tokens 和 11,672 个未缓存输入共增加 $0.007160400，超过输入节省。
压缩动作所在请求总费用为 $0.001995606，其中输出 875 tokens；这里不把该
请求的全部输出、输入或未来变化虚称为独立的“摘要模型调用”。

压缩后首请求有 3,174 个未缓存输入、384 个缓存输入，存在实际的重新预填成本。
两边首个续作请求都读取 477,952 个缓存 tokens，公共过去确实已暖；完整分支
保留的长历史也因此非常便宜。服务商缓存不因客户端分叉就完全独立。

结构性费用差已由账本确认；调用数和输出差来自两条自由执行的模型轨迹。
轨迹直接显示 active 有 24 次工具调用、5 次代码写入和 3 次检查失败后恢复；
inactive 有 5 次工具调用、一次代码写入且工具命令全部成功。没有压缩重复提交
或收据重试。更细的修改/验证过程见 [轨迹诊断](trajectory-analysis.md)。单次配对不能把
这些路径差异直接归因为摘要丢失信息或模型能力下降，也不足以判定最优算法。

## 共同费用与结论范围

- 共同准备 C_P：$0.071709600，仅在实际支出中计一次。
- 两条续作 C_I/C_A：$0.011411280/$0.012177312。
- 实际实验支出 `C_P+C_I+C_A`：**$0.095298192**。
- 条件归因 `C_P+C_I` / `C_P+C_A`：$0.083120880/$0.083886912，差约 0.92%。

主观察是同一给定状态后的续作节省率 **−6.7129%**。上述条件归因不是从头
独立部署的完整任务费用，因为此前自然模型调查没有测量。单组顺序固定为
inactive→active，后者可享受共同过去的缓存；模型随机性与共享缓存均限制外推。
不重跑挑选正收益、不移除多调用，原结果完整保留。

下一步应减少重复探索与代码修改循环、提高摘要的可续作性，并保持独立验收
标准。按质量达标后的最终任务费用衡量回本，而非只追求输入压缩率；算法因果与稳定收益还需重复
和其它场景验证。此次没有额外发起模型调用。

证据：[请求账本与费用曲线数据](request-costs.csv)、[完整汇总](raw/summary.json)、
[独立对账](raw/independent-audit.json)、[预注册协议](raw/protocol.json)。
