# 费用上升与平均上下文长度的补充分析

数据来自冻结的 36 次 pilot；没有新增模型调用。上下文长度采用官方 usage 中
`uncachedInputTokens + cacheReadTokens`，包括 system、工具定义和消息，按请求加权。
DCP 一次请求没有 usage，其长度不猜测、不按零；DCP 均值仅覆盖 576 个已知请求。

| 指标                                        | 不使用 DCP  | 使用 DCP    |
| ------------------------------------------- | ----------- | ----------- |
| API 请求尝试                                | 449         | 577         |
| 有完整 usage 的请求                         | 449         | 576         |
| 平均完整输入/上下文 tokens                  | 16227.01    | 18612.60    |
| 平均未缓存输入 tokens                       | 429.13      | 401.26      |
| 平均输出 tokens                             | 439.44      | 417.38      |
| 平均已知请求费用 USD                        | 0.000375428 | 0.000365251 |
| 先算每运行均值再对18运行平均的上下文 tokens | 9522.81     | 12320.26    |
| 累计已知输入 tokens（含缓存）               | 7285927     | 10720855    |
| 累计已知输出 tokens                         | 197309      | 240411      |
| 已知费用 USD                                | 0.168566994 | 0.210384834 |

主口径平均输入增加 14.70%，请求尝试增加 28.51%；已知请求平均输出下降 5.02%，
平均费用下降 2.71%，但累计已知输出增加 21.84%、输入增加 47.14%。因此账本能确认
的费用上涨主要来自更多调用与其累计用量，而不是单次回复更长或单次调用平均更贵。
按运行平均和按请求平均回答不同问题，不能混用；后者让长任务/后期请求占更大权重，
上下文均值差不能直接解释成插件为同一状态添加了 2385.59 tokens。

| 已知费用组成 | baseline USD | DCP USD     | 增量 USD    | 占已知增量 |
| ------------ | ------------ | ----------- | ----------- | ---------- |
| 未缓存输入   | 0.028901850  | 0.034669050 | 0.005767200 | 13.79%     |
| 缓存读取     | 0.021279744  | 0.031469184 | 0.010189440 | 24.37%     |
| 输出         | 0.118385400  | 0.144246600 | 0.025861200 | 61.84%     |
| 合计         | 0.168566994  | 0.210384834 | 0.041817840 | 100%       |

两臂全部处于同一 off-peak 价窗，没有峰谷价格造成的假增量。DCP 已知费用相比
baseline 总费用增加 24.81%；精确总费还有一笔未知，不能把该比较写成精确总增幅。

用 baseline 平均费用作基准，将已知费用差恒等分解：额外 127 个已知请求贡献 +$0.047679306，候选平均单次费用下降抵消 −$0.005861466，净 +$0.041817840。
这只是账本分解，不是对提示词作用的因果估计。

本轮没有 compress、prune 或历史替换，因此没有实际压缩带来的节省来抵消开销。
两臂从开始就有不同的工具定义、规则和初始 marker，执行路径也不同；更多调用究竟
由插件提示引起多少、随机路径差异占多少，当前从头 A/B 无法确定。应通过提示词/
工具定义/marker 消融，以及同休眠前缀 fork，再区分直接输入开销与策略行为效果。

## 同状态起点与主要贡献任务

[独立补充审计](raw/cost-context-audit.json)对 18 个同题/同重复的首请求作配对：baseline
均值 589.56 tokens，DCP 1235.56 tokens，18 个差值全为 +646 tokens。首次请求还没有
后续工作轨迹差异，这是规则、工具定义与 marker 合计的直接输入开销代理；没有把
平均全过程的 +2385.59 tokens 全部归因于提示词。后续分支工作内容与步骤不同，
不能据此推算精确的静态开销计费或断言每个后续请求差值恒为 646。

| 任务（两次重复合计）      | DCP 超额请求尝试 | 已知费用差 USD |
| ------------------------- | ---------------- | -------------- |
| cancel-async-tasks        | +45              | +0.017827506   |
| sqlite-db-truncate        | +31              | +0.010905468   |
| cobol-modernization       | +27              | +0.009466506   |
| break-filter-js-from-html | +23              | +0.004011828   |

前两题合计约占已知费用增量的 68.7%。COBOL 含未知费用，其差值为下界。
只做每次运行内命令归一化后的精确指纹重复检测：baseline 491 个 terminal call
中有 2 个额外重复，DCP 609 个中有 4 个，无相邻重复或精确重复 test 命令。
这不能排除不同写法的语义重复，也不足以把额外步骤都判为无用反复检查。

每个 DCP run 的唯一来源消息追加均在首请求前；结合 `src/index.ts` 的 step=1
marker 路径与当前低压力配置，本轮没有反复注入压缩催促。实际压缩和自动剪枝
均为零。当前数据能定位计费增量与直接起始输入开销，插件对规划轨迹的因果作用
仍需消融和公共休眠前缀 fork 检验。
