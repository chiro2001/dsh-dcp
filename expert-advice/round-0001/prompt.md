# Round 0001 prompt — dsh-dcp 开发规划修订咨询

你是 dsh-dcp 项目的顶级审阅/修订模型。dsh-dcp 是 DeepSeek Harness（dsh）的
动态上下文管理插件，对标 opencode-dcp 的原理与实现。当前处于**规划阶段**，
仓库内只有 `docs/PLAN.md`（详细实现规划）与 `README.md`，尚无代码。

请阅读 `context.md` 列出的输入，然后完成以下任务。

## 1. 你的审阅职责

针对现有 `docs/PLAN.md`，至少给出：

1. **整体反驳与批评**：规划的结构、核心决策（尤其“全部模型可见内容走会话日志 /
   surface replace / `dcp/*` log-only 事件 / 系统提示承载边界索引与 nudge”）、
   里程碑划分与测试策略，哪些成立、哪些值得怀疑、哪些论证不充分；
2. **最可能被遗漏的正确性/集成风险**：dsh 事件系统与表面替换、工具执行管线、
   权限/审批、子代理、并发与重入、进程重启重建、与 dsh 原生 compaction 的
   交互、KV cache 影响、会话日志版本与 `ignorable` 语义等；
3. **按信息增益排序的 1–3 个“下一个实验/原型”**：在开始 M1 大规模编码前，
   哪些最小实验（可写测试或小原型）能最快证伪/证实规划中的关键假设；
4. **方向性判断**：是否需要改变方向（例如是否应扩展 dsh 核心、是否应改用
   请求时改写、消息边界方案是否需要换成逐条 tag、摘要是否应由插件自调用
   模型而非模型内联等）；
5. **明确区分**：“由现有文件支持的事实”“推断”“需要实验验证的建议”三类
   内容，逐条标注，不得混为一谈。

## 2. 交付物

1. **修订摘要**：列出你修改了规划中的哪些部分、为什么（对应审阅意见编号）；
2. **完整修订版 PLAN 全文**：可以作为 `docs/PLAN.md` 的直接替换内容，保持
   可执行的详细程度（架构决策、事件模型、功能映射、模块结构、里程碑、测试
   与 CI、配置、风险），结构允许重排、增删，但要保留足以指导后续实现的信息；
3. 对每个建议标注上面第 1 条的类别（事实/推断/需实验）。
